## v1.12 — 修复语音会话提前收口

**versionCode 23 / versionName '1.12'**

**问题**：按住 🎤 持续说话时，话没说完面板就自动收回。

**根因**（两条独立缺陷叠加）：

1. `onFinishInput` 被当作"失焦/窗口隐藏"处理而无条件取消语音会话。但该回调实际只代表**输入上下文重启**（分句上屏后部分 ROM 会重建输入会话），并不代表 IME 窗口消失——用户手指仍按着，会话却被取消。
2. 音频采集 `AudioRecord.read` 返回 `0`（瞬时繁忙）或负值（错误码）时被直接当作"用户松手"处理，静默走正常收口路径。

**修复**：

- `onFinishInput` 在语音会话活跃（按住中或面板显示）时**跳过**取消；窗口真消失仍由 `onFinishInputView` / `onWindowHidden` 无条件兜底，麦克风不会驻留。
- 音频读取异常改为**重试 + 明确错误收口**：连续 `0` 值 100 次（约 1 秒）或连续错误码 3 次才判为通道中断，弹出「录音通道中断，请重试」，**不再静默冒充正常收口**。
- 补充防御：错误收口后迟到的中间分句不再上屏。

## v1.11 — 🎤 按住说话（微信式交互）

**versionCode 22 / versionName '1.11'**

**变更**：🎤 从「点击开始 / 再点结束」改为**按住说话**——按住时聆听、松开时识别上屏。

**交互说明**：

| 手势 | 行为 |
|---|---|
| 按住 🎤 | 开始聆听，面板显示「请说话，松开结束」 |
| 说话中停顿 | VAD 断句，该句**立即上屏**，会话继续 |
| 松开 🎤 | 补上最后一段并收起面板 |
| 按住后滑出 / 返回键 | 取消本次输入 |

**技术要点**：

- **采集 / 解码解耦**：解码移入单线程执行器按序执行，音频缓冲扩至 2 秒，避免长句解码阻塞采集导致丢音频
- **连续会话 VAD 模式**：`while (!vad.empty())` 出段即异步提交解码，不结束会话
- **终结信号语义**：仅收口段触发终结，中间分句不上锁
- 修复：识别中（DECODING）态点击面板热区不再导致尾句丢失

## v1.10 — 语音面板四态状态条

**versionCode 21 / versionName '1.10'**

**问题**：点 🎤 后面板"像 PPT 一样自动播放几帧就停了"。

**根因**：不是定时器，而是旧面板把三种完全不同的状态（模型加载中 / 正在倾听 / 识别推理中）显示成了同一句「倾听中，点击结束」。

**变更**：

| 真实状态 | 旧显示 | 新显示 |
|---|---|---|
| 模型首次加载（约 241 MB） | 倾听中，点击结束 | **正在准备离线模型 N%** |
| 正在录音、等用户说话 | 倾听中，点击结束 | 请说话（状态条随音量变化） |
| VAD 断句、ASR 推理中 | 倾听中，点击结束 | **识别中…** |
| 错误 | 无区分 | **明确错误文案** |

- 落实「按多久显示多久」：识别成功**立刻收面板**；失败/空结果**停留 3 秒**再收（可随时打断）

## v1.9.1 — JNI 字段契约缺陷修复（P0）

**versionCode 20 / versionName '1.9.1'**

**问题**：v1.9 语音路径 100% 不可用。

**根因**：sherpa-onnx 的 JNI 对一批字段是**无条件** `GetFieldID`——缺少任意一个即抛 `RuntimeException: Failed to get field ID for <name>`。v1.9 只验证了「已存在的字段能被找到」，未验证「字段是否完整」，导致 13 个必需字段缺失。

**修复**：补齐全部 13 个缺失字段（`modelType` / `tokenizer` / `modelingUnit` / `bpeVocab` / `teleSpeech` / `decodingMethod` / `maxActivePaths` / `hotwordsFile` / `hotwordsScore` 等）。

**方法**：直接从 `libsherpa-onnx-jni.so` 提取所需字段名清单——这是最可靠的契约验证方式：

```bash
strings -a libsherpa-onnx-jni.so | grep -oE "Failed to get field ID for [A-Za-z0-9_]+" | sort -u
```
